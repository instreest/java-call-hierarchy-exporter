# 機能仕様ごとの実装難易度と省略の目安

再実装を依頼するときに、自分のプロジェクトでは不要な機能を省く判断に使うための一覧です。
[prompt-A-minimal.md](prompt-A-minimal.md) / [prompt-B-detailed.md](prompt-B-detailed.md) の
節番号で対応箇所を示します。省く場合は、その節と第3部の該当テストをプロンプトから削ってください。

難易度の目安:

| 難易度 | 意味 |
|---|---|
| 低 | 仕様どおりに書けば動く。落とし穴が少ない。数十〜百数十行 |
| 中 | 落とし穴があり、踏むと出力が静かに欠ける。参照実装のはまりどころ（プロンプトB第2部）を読む必要がある。百〜数百行 |
| 高 | 設計判断が結果の正しさを左右する。経路依存・複数ファイルにまたがる状態・安全側への倒し方を理解して書く必要がある。数百行〜 |

「実装量」は参照実装（`src/jche/`、合計約 9,000 行）の該当部分の規模です。
「省いた場合」は、その機能を外したときに出力がどう変わるかです。**目的（改修時の影響調査で
呼び出しを漏らさない）に対して何を失うか**で判断してください。

## 省略パターンの例

| 状況 | 省いてよいもの | 残すもの |
|---|---|---|
| 小規模（数千ファイル以下）で、毎回全件解析してよい | 4 全部（キャッシュ・差分更新・メモリ設計・バッチ化） | 1, 2, 3 |
| インターフェース経由の呼び出しが少ない（具象クラスを直接呼ぶコードベース） | 2-5〜2-9 | 2-1〜2-4（CHA と注記は残す） |
| リフレクションを使わない | 2-9 | — |
| 他チームの jar を見ない | 5 全部 | — |
| 単一環境で使い捨て、CSV の diff を取らない | 3-4 | — |
| 独自フレームワークのディスパッチが無い | 2-10 | — |
| 起点を常に `entry.packages` で指定する | 3-2（ただし `methods.csv` の入次数は残す） | 3-1 |

どの構成でも、**1-9（型解決失敗を行として残す）と 2-2（絞れなかった理由の注記）は残す**ことを
勧めます。この2つが無いと「出ていない＝呼んでいない」と誤読し、影響調査の結論を誤ります。
