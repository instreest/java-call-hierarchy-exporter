# entry.packages / exclude.packages の途中のワイルドカード

（Issue なし。利用者からの要望: `exclude.packages` の文字列の途中に `*` を書いて、任意のパッケージに続くパッケージを指定したい）

## 対応の要点

- `entry.packages` / `exclude.packages` のパターン（`jche.config.PackagePattern`）の、末尾の `.*` / `.**` より前
  （クラス指定・メソッド指定では `#` より前）に `*` を書けるようにした
  - 階層全体が `*` … 任意の 1 階層（`jp.co.*.dao.**` は `jp.co.a.dao`・`jp.co.b.dao.impl` に当たり、`jp.co.dao`・`jp.co.a.b.dao` に当たらない）
  - 階層全体が `**` … 任意の 0 階層以上（`jp.co.**.dao.*` は `jp.co.dao`・`jp.co.a.b.dao` の直下に当たる）
  - 階層の一部の `*` … `.` を含まない任意の文字列（`jp.co.xxx.*Impl` は `jp.co.xxx` の、名前が `Impl` で終わるクラス）
- クラス指定・メソッド指定では、ワイルドカードがパッケージを越えて外側のクラス名を飲み込まない（Q5）
- `*` は `$` をまたがない（匿名クラス・ローカルクラスの `Foo$1` に当たらない。Q8）
- 文字の階層が 1 つも無い指定（`*`・`**.**`・`*.**` など）、`#` の前の最後の階層が `**` の指定、メソッド名（`#` の後ろ）の `*` は
  何にも当たらず、`warnings.txt` の専用の項目に警告を出す（Q6・Q9）
- 途中の `*` / `**` は 1 ファイル版では使えない（Q10）
- 末尾の `.*`（直下）・`.**`（配下）・クラス指定・メソッド指定の意味は変えていない。`*` を含まない指定も同じ照合（階層ごと）を通り、以前の文字列の比較と同じ答えになる（Q7）
- 検査は `test/pattern/run.sh`（当たる例と当たらない例、以前の照合との突き合わせ、書き間違いの知らせ）

## Q&A

### Q1. 途中の `*` は 1 階層か、何階層でもよいか

**1 階層にした。** 何階層でもよい書き方は別に `**` として用意した。Ant・Spring の `AntPathMatcher`・
AspectJ のパッケージ指定と同じ使い分けで、末尾の `.*`（直下）・`.**`（配下）とも揃う。`*` を何階層でも当たる意味にすると、
`jp.co.*.dao.**` が `jp.co.a.b.dao` まで拾い、除外が利用者の思ったより効きすぎる。除外が効きすぎると呼び出しが
静かに出なくなる（このツールでいちばん避けたい壊れ方）ので、狭い方を既定にした。

### Q2. 文字列全体を正規表現にしないのはなぜか

`.` で区切った階層単位で照合している。正規表現（`*` を `.*` に置き換える）にすると、`*` が `.` をまたいで
`jp.co.*dao` が `jp.co.x.ydao` に当たってしまう。階層の中の `*` は `.` を含まない文字列に限り、パターンの `*` 以外の文字
（`$` など）は文字どおりに比べる（`Pattern.quote`）。

### Q3. メソッド名に `*` を書けないのはなぜか

要望が「パッケージの途中」だったことと、メソッド名の `*` は `get*` のように除外を広く効かせすぎやすく、
除外したメソッドの先は親に繋ぎ直されるだけで行は出なくなるので、影響を見落としやすいため。必要になったら
同じ `Segment` の照合を `methodName` にも使えば足せる。書いた場合は何にも当たらないので、黙らずに警告する（Q6）。

### Q4. 照合の重さは

照合は出力の木を辿るノードごと（`StreamingTreeWalker`）・サーバーの辺ごと（`CallTree`）に呼ばれる。
名前は分割せず、文字列の中の位置で階層を比べる（Q7 の末尾）。`*` を含まない階層は文字の比較（`startsWith` の位置指定）、
階層の一部の `*` は、よく書く形（`*` だけ・前方一致 `Foo*`・後方一致 `*Impl`）を正規表現を使わずに比べ、それ以外の形
（`a*b*c`）だけ正規表現をその階層の範囲（`Matcher#region`）で使う（照合のたびに `Matcher` を作らないため）。
名前の階層の数と始まりの位置は `matchesAny` が名前 1 つにつき 1 回だけ数え、すべてのパターンで使い回す。
`**` を含まない指定（既定の `java.**` など大半）は表を作らず先頭から比べる。`**` を含む指定は「パターンのここまでで
名前のどこまで来られるか」の表（2 本を入れ替えて使う）を 1 段ずつ進めるので、手数はパターンの階層数 × 名前の階層数で頭打ちになる
（素直な後戻りだと `**.**.**.x.**` のような指定で組み合わせの数だけ増える）。続く `**` は読み込むときに 1 つにまとめる。
キャッシュの事実は変わらないので `CacheFormat.VERSION` は上げていない（読み手だけの変更）。

### Q5. クラス指定の `*` / `**` は外側のクラス名に当たるか

**当たらない。** 型の FQN（`jp.co.app.Outer.UserDao`）を階層ごとにそのまま比べると、`jp.co.**.UserDao` の `**` が
`app.Outer` を飲み込み、利用者が「どこかのパッケージの UserDao」のつもりで書いた指定が入れ子のクラスまで除外する。
除外の効きすぎは呼び出しが静かに消える壊れ方なので、型をパッケージの部分とクラス名の部分に分け、パターンの後ろの
クラス名の階層数ぶんをクラス名に、残りをパッケージに合わせる。クラス名の部分では `**` は当たらず、`*` はいちばん内側の
クラス名にだけ書ける（`jp.co.*.*Impl` は `jp.co.x.FooImpl` に当たり、入れ子の `jp.co.Outer.FooImpl` に当たらない）。
入れ子を指すときは `jp.co.**.Outer.UserDao` のように外側のクラス名を書く。

途中の階層の `*` に大文字が混じる指定（`jp.co.**.*Outer.Inner`）は、外側のクラス名のつもりで書いたことが多いが、この決まりで
入れ子のクラスには当たらない（`*Outer` はパッケージ名として比べるので、名前が `Outer` で終わるパッケージの `Inner` にだけ当たる）。
黙っていると起点が出ない理由が分からないので、警告する（パッケージ名に大文字を使うこともありうるので、照合はやめない）。
大文字を目印にするのは、Java の慣習でパッケージ名は小文字、クラス名は大文字で始まるため。

### Q6. `*` / `**` だけの指定はどう読むか（2 回目のレビューで広げた）

**以前どおり何にも当たらない指定とし、警告を出す。** 途中のワイルドカードの規則をそのまま当てると `**` は全部に当たり、
`exclude.packages` に紛れ込むだけで出力が黙って空になる。以前は何にも当たらず、`entry.packages=*` なら「entry.packages の
指定を確認してください（ワイルドカード）」が出ていた。意味を広げず、書き間違いとして警告する。`.**`（パッケージ名なし）も以前どおり無名パッケージだけに当たり、全部には広げない。メソッド名の `*`（`UserDao#get*`）も
同じく何にも当たらないので警告する。設定を読む時点（`Config`）では `run.log` も `warnings.txt` もまだ無いので、文言だけを
`Config#patternWarnings` が作り、解析の始めに `jche.Exporter` が `Warnings.warn(Topic.PATTERN, …)` で出す（CLI とサーバーの両方が通る）。

警告を載せる `warnings.txt` の項目は、最初は設定の項目（`Topic.CONFIG`）にしたが、その見出しと対処は「指定したフォルダ・
ファイルが無い」「相対パスの起点」の話で、書き間違いを直したい利用者を違う方向へ案内する。パターン用の項目
（`Topic.PATTERN`。見出し「指定が何にも当たらない」、影響「起点ができない・除外されない」、対処「各行の案内に沿って書き直す」）
を別に立てた。

最初は `*` と `**` の単独だけを止めていたが、`**.**`・`*.**`・`**.*` も同じく全部（`*.**` は名前のあるパッケージ全部）に当たり、
この PR より前はどれも何にも当たらなかった（`**` という名前のパッケージとして比べていた）。**文字の階層が 1 つも無い指定**を
まとめて「何にも当たらない＋警告」にした。

さらに 3 回目のレビューで、`***` のように `*` を 3 つ以上並べた階層が漏れていた（照合では任意の 1 階層なのに、判定では
`*` / `**` と書いた階層しか数えていなかった）。判定と照合で階層の読み方を 2 通り持っていたのが原因なので、判定は照合に使う
階層（`Segment`）から決める形にした（`*` だけでできた階層は、何個並べても任意の 1 階層として読み、文字の階層に数えない）。

### Q7. `*` を含まない指定は別の照合にしないのか

**しない。** 最初は `*` を含まない指定を以前の文字列の比較のまま残し、含む指定だけ階層ごとに比べていたが、末尾の
`.*` / `.**`・クラス指定の決まりを 2 か所で揃え続けることになる（Q5 の入れ子の扱いも 2 か所に要る）。`*` を含まない指定は
「全部の階層が文字だけの指定」として同じ照合を通す。答えが以前と同じことは、`test/pattern` が以前の照合を写した関数と
すべての組み合わせで突き合わせて見る（`.**` が全部に当たるように変わっていたのを、この突き合わせで見つけた）。

照合は名前を分割せず、文字列の中の位置で階層を比べる。`**` を含まない指定（既定の `java.**` など大半）は配列も部分文字列も
作らない。`**` を含む指定だけ、各階層の始まりの位置の表と到達表を作る。`*` を含まない指定を以前の `startsWith` / `equals` に
戻す案もあったが、照合がまた 2 本になるので採らなかった（どこに `**` があるかは読み込むときに 1 回求めておく）。

### Q8. `*` は `$` をまたぐか

**またがない。** JDT は匿名クラス・ローカルクラスを `fx.app.Main$1LocalService` のような名前で持ち、この名前が型の FQN として
照合に来る。`*` が `$` をまたぐと、`jp.co.x.Foo*`（`FooHelper` などのつもり）が `Foo$1`（`Foo` の中の匿名クラス）にも当たり、
名前を挙げていない型の呼び出しまで除外する。以前のクラス指定は `$N` の名前に当たらなかったので、新しくできた効きすぎになる。
階層の中の `*` は `.` と `$` を含まない文字列にした。匿名クラスを指したいときは `Foo$*` のように `$` を書く。

### Q9. `#` の前の最後が `**` の指定（`jp.co.app.**#execute`）は

Q5 のとおりクラス名の部分の `**` は当たらないので、何にも当たらない。`jp.co.app` 配下の全クラスの `execute` のつもりで書くと
起点が 0 件になり、黙っていると気づけないので警告する。「どのクラスでも」の意味で読む案は、`**` がクラス名の部分に当たらない
決まり（Q5）と食い違うので採らなかった。直下のクラスなら `jp.co.app.*#execute` と書ける。

### Q10. 1 ファイル版（`single-file/`）は

決まり（`docs/single-file-qa.md` の Q8。本体と同期を取らない場合がある）どおり直していない。1 ファイル版は末尾の `.*` / `.**`
だけを読むので、途中の `*` を書くと「その名前のパッケージ・クラス」として比べて何にも当たらない。1 ファイル版も同じ
`config/jche.properties` を読むので、そのコメントに「1 ファイル版では使えない」と書き添えた。

### 却下した案

- **`*` を何階層でもよい意味にする** … Q1 のとおり除外が効きすぎる
- **`?`（任意の 1 文字）や `{a,b}` も入れる** … 要望が無く、カンマ区切りの設定値と `{a,b}` のカンマがぶつかる
- **`*` / `**` だけの指定を「全部」と読む** … Q6 のとおり、紛れ込むだけで出力が黙って空になる
- **`*` を含まない指定を以前の文字列の比較に戻す（速さのため）** … Q7 のとおり照合が 2 本になる。位置で比べて配列を作らない形で足りる
