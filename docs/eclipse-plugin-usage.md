# Eclipseプラグインの使い方

このツールは **Eclipse プラグインとしても使える**。パッケージ・エクスプローラーやエディタから
メソッドを選び、その**呼び出し元を階層で辿る**のが主な使い方である。

Eclipse を使わない通常の利用（コマンドラインで CSV を出す）はリポジトリ直下の
[README.md](../README.md) を参照のこと。**プラグインは付加的な使い方**なので、
その説明はこの文書にまとめてある。

## 1. 動作条件

**解析は Eclipse の中では走らない。** プラグインは同梱した解析本体（`lib/jche-core.jar`）と
JDT 一式（`lib/jdt/*.jar`）を、別の JDK で子プロセスとして起動し、結果だけを受け取る。
そのため **Eclipse 側の JDT や JDK の版は、解析できる Java の版に影響しない**。

| | 条件 |
|---|---|
| Eclipse | **4.17（2020-09）以降** |
| Eclipse を動かす JDK | **11 以上**（プラグインは Java 11 でコンパイルしている） |
| 解析に使う JDK | **17 以上、推奨 25**。「設定 → JAVA_HOME → 取得済み → Eclipse を動かしている JVM → PATH の java」の順に探す |
| 表示言語 | **英語が既定**。Eclipse が日本語で動いていれば日本語（§3.1） |

Pleiades はどの版（2020 以降）でも条件を満たす。同梱の JDK がそのまま解析にも使える
（2023 以降は 17・21、2025 以降は 25）。
見つからなければ設定画面から取得できる（§4）。

## 2. 入れる

### 方法A: jar を作って Eclipse に入れる（おすすめ）

必要なもの: Git、JDK 21 以上、Maven、ネットワーク（初回だけ依存の取得に使う）。
（ビルドに使う JDK の話で、できあがったプラグインが要求するのは Java 11 以上である）

```bash
git clone https://github.com/instreest/java-call-hierarchy-exporter.git
cd java-call-hierarchy-exporter
mvn -f eclipse-plugin/pom.xml package
# -> eclipse-plugin/target/io.github.instreest.jche.eclipse-1.0.0.jar（約 12MB）
```

Eclipse を終了してから、その jar を Eclipse インストール先の `dropins` フォルダへコピーし、
初回だけ `-clean` を付けて起動する。

```bat
rem Windows（Pleiades の例。パスは環境に合わせる）
copy eclipse-plugin\target\io.github.instreest.jche.eclipse-1.0.0.jar C:\pleiades\2026-06\eclipse\dropins\
C:\pleiades\2026-06\eclipse\eclipse.exe -clean
```

入ったかどうかは「ヘルプ → Eclipse IDE について → インストール詳細 → プラグイン」で
`io.github.instreest.jche.eclipse` を探せば分かる。

### 方法A': GitHub Actions で作らせて jar を持ち帰る

手元に Maven やネットワークが無いときは、このリポジトリの
[`eclipse-plugin-jar`](../.github/workflows/eclipse-plugin-jar.yml) ワークフローを使う。
GitHub の「Actions → eclipse-plugin-jar → Run workflow」で手動実行すると、
方法Aと同じ jar が `eclipse-plugin-jar` アーティファクト（zip）として付く。
展開して出てきた jar を、方法Aと同じように `dropins` へ置く。

アーティファクトの保持日数はリポジトリの既定（通常 90 日）に従う。

### 方法B: Eclipse（PDE）で開いて開発する

PDE（プラグイン開発環境）入りの Eclipse が要る。

1. 先に `mvn -f eclipse-plugin/pom.xml package` を実行し、`eclipse-plugin/target/classes/lib/` を
   `eclipse-plugin/lib/` へコピーする（解析本体と JDT はここから同梱される）
2. 「ファイル → インポート → 一般 → 既存プロジェクトをワークスペースへ」で `eclipse-plugin` を選ぶ
3. 試すときは「実行 → 実行構成 → Eclipse アプリケーション」、配布物を作るときは
   「ファイル → エクスポート → デプロイ可能なプラグインおよびフラグメント」

PDE がコンパイルするのは `src-ui/`（プラグイン）だけである。解析本体（リポジトリ直下の `src/`）は
Java 17 でコンパイルして `lib/jche-core.jar` に収めるものなので、PDE のビルドには含めない。

## 3. 使う

### 3.1 表示言語

画面の文言は**英語が既定**で、**Eclipse が日本語で動いていれば日本語**になる。
Pleiades を使っているかどうかは関係ない（Pleiades は Eclipse 本体の文言を訳す仕組みで、
個別のプラグインの文言は訳せない。[eclipse-plugin-nls-qa.md](eclipse-plugin-nls-qa.md) の Q1）。

判断に使うのは Eclipse の表示言語（`-nl` / eclipse.ini の指定。無ければ OS の言語）である。
英語の Eclipse で日本語にしたい（あるいはその逆）なら、eclipse.ini で切り替える。

```
-nl
ja
```

eclipse.ini は**1行に1つの引数**を書く形式で、コメントは書けない。上の 2 行は
`-vmargs` より前に置くこと（`-vmargs` 以降は JVM への引数になる）。

日本語・英語以外の言語では英語が出る。訳を足したい場合は、プラグインの中の
`jche/eclipse/messages.properties` を写して `messages_<言語>.properties` を作れば、その言語で出る。

解析そのもののログ（コンソールと `analysis-*.log`）と、解析の失敗理由の本文は日本語のままである
（同 Q6）。

### 3.2 操作

入口は 2 つある。**メソッドから入る**のが主な使い方で、**ビューから入る**こともできる。

### メソッドから入る（主な使い方）

1. 解析したいメソッドにカーソルを置く（またはパッケージ・エクスプローラー／アウトラインで選ぶ）
2. 右クリック →「**影響調査: 呼び出し元階層を表示**」（`Ctrl+Alt+Shift+H`）
3. 「影響調査 (Call Hierarchy Exporter)」ビューが開く。まだ解析していなければ、一番上の［解析する］から始める
4. 解析は別プロセスで走る（Eclipse の操作は止まらない。［中止］もできる）。終わると呼び出し元が
   **すべて展開された**ツリーで出る。ダブルクリックでその**呼び出している行**へ飛べる

### ビューから入る

「ウィンドウ → ビューの表示 → その他 → 影響調査 (Call Hierarchy Exporter)」で開く。

1. 一番上の［**対象プロジェクト**］で解析するプロジェクトを選ぶ
   （エディタを開いていれば、そのプロジェクトが最初から選ばれている）
2. 同じ行の［解析する］。メソッドを決める前に、解析だけ先に済ませておける
3. 解析が済んだら、エディタでメソッドにカーソルを置いて［**カーソル位置のメソッド**］を押す
   （ツールバーの ◎。解析直後はバナーにも出る）

解析前に出るのはこの行（対象プロジェクト・設定・［解析に使う設定…］・［解析する］）だけである。
解析が済むと［解析する］は引っ込み、木が画面いっぱいに出る。

設定ファイルは**無くてよい**。Java プロジェクトなら、ソースフォルダ・依存 jar・文字コード・
コンパイラー準拠レベルをプロジェクトの構成から自動で組み立てる。
**ソースフォルダが `src/main/java` でなくても、Eclipse のビルド・パスに載っていれば解析できる。**

| したいこと | 操作 |
|---|---|
| 対象のプロジェクトを変える | 一番上の［対象プロジェクト］ |
| 何を見て解析しているか確かめる | ［解析に使う設定…］。起点・ソースフォルダ・依存 jar がそのまま出る。設定ファイルへの切り替えと、内容の保存もここから |
| 向きを変える | ツールバーの ↑（呼び出し元）／↓（呼び出し先）。いまどちらを見ているかは、押されているほうで分かる |
| 表示中のメソッドを変える | ツールバーの ◎［カーソル位置のメソッド］（エディタのカーソル位置・選択から拾う） |
| 木を開く・閉じる | ツールバーの［すべて展開］／［折りたたむ］。最初から全部開いた状態で出る |
| 解析し直す | ツールバーの ⟳［再解析］。**押すまで表示は変わらない**（勝手に解析し直すことはない） |
| **解析をリセットする** | ツールバーの 🗑［リセット］。確認のうえで解析結果を捨て、解析前の画面に戻る。ディスクのキャッシュは残るので、次の解析は速く終わる |
| キャッシュのファイルごと消す | 設定画面（▽ →［設定（JDK・置き場所）…］）の［解析キャッシュを削除］。次の解析は初回と同じだけかかる |
| **行をコピーする** | 選んで `Ctrl+C`（または右クリック →［コピー］）。**階層の字下げ付き**で貼れる。右クリック →［この行から下をコピー］なら、畳んでいる行も含めてまとめて取れる |
| 見えている木を CSV に | 右クリック →［この呼び出し階層をCSVに出力…］。画面の 1000 行の上限は掛からない（全部出る） |
| 置き場所や JDK を変える | ビューのメニュー（▽）→［設定（JDK・置き場所）…］ |

木は**すべて展開して 1000 行まで**出す。深さやフィルタの指定は無い（[やめた理由](eclipse-plugin-ui-simplify-qa.md) の Q5）。
1000 行で打ち切ったときはバナーでそう言うので、全部見たいときは CSV に出す。

設定の優先順位は **①ビューで選んだ設定ファイル → ②プロジェクトの `config/jche.properties`
（無ければ `config/config.properties`、直下の `jche.properties`、直下の `config.properties` の順）→
③プロジェクト構成からの自動生成**。どの設定で解析したかは、対象バーの「設定: …」に出る
（そのツールチップに、解析プロセスの JDK・JDT の版とキャッシュ・ログの場所も出る）。

②で自動的に使うのは、このツールの項目（`project.root` / `source.folders` / `entry.packages` のどれか）を
持つファイルだけ。`config.properties` は解析対象のプロジェクトが自前の設定に使っていることがあり、
それを取り違えないためである（別物だった場合は③の自動生成で動く。ビューで明示的に選んだファイルは
この判定を通さず、そのまま使う）。保存するときの名前を `jche.properties` にしているのも同じ理由。

**解析結果は、捨てるまで消えない。** ソースを直しても、しばらく放っておいても、勝手に解析し直したり
結果を捨てたりはしない。解析後に変わったファイルの行には ⚠ が付き、内容が古い可能性があることが
行単位で分かる（解析し直すかどうかは ⟳ を押す人が決める）。

結果が消えるのは次の 4 つだけである。
［リセット］／［再解析］／解析プロセスの設定（JDK・VM 引数・キャッシュの置き場所）を変えて［OK］／
設定画面の［解析キャッシュを削除］。理由は
[eclipse-plugin-ui-simplify-qa.md](eclipse-plugin-ui-simplify-qa.md) の Q1・Q8。

## 4. 設定（ウィンドウ > 設定 > 影響調査 (Call Hierarchy Exporter)）

ビューの［▽］メニュー →［設定（JDK・置き場所）…］からも開ける。
決められるのは「**解析をどう走らせるか**」と「**作ったファイルをどこへ置くか**」の 2 つである
（何を解析するかは設定ファイルの役目で、そちらはビューの［解析に使う設定…］）。

### 解析プロセス

| 設定 | 既定 | 用途 |
|---|---|---|
| 解析に使う JDK | 自動（25 を優先して 17 以上） | CLI と結果を揃えたいとき。**見つからなければ［JDK 25 を取得…］で Adoptium から取得できる**（約 200MB、確認してから実行。閉域では場所を指定する） |
| 解析プロセスの JVM 引数 | 無し | `-Xmx4g` など。Eclipse 自身のメモリとは別枠 |

解析に使う JDT は**同梱のものに固定**である（差し替える設定は廃止した。
[eclipse-plugin-ui-simplify-qa.md](eclipse-plugin-ui-simplify-qa.md) の Q9）。
解析プロセスは、終わらせるまで常駐して解析結果を持ち続ける。時間で勝手に終わることはない。

### 置き場所

3 つとも**空欄でよい**（既定はワークスペースの中）。空欄でも実際のパスが行の下に出て、
隣の［開く］でそのフォルダを開ける。閉域の共有フォルダに置きたいときや、
ワークスペースを作り直してもキャッシュを残したいときだけ指定する。

| 設定 | 既定（`<状態フォルダ>` = `<ワークスペース>/.metadata/.plugins/io.github.instreest.jche.eclipse`） | 中身 |
|---|---|---|
| 解析キャッシュ | `<状態フォルダ>/cache` | この下の `.cache/<プロジェクト名>_<識別子>/` に `analysis-cache.tsv` と `dataflow-cache.tsv`。消しても次の解析で作り直す（時間はかかる）。隣の［解析キャッシュを削除］で、この `.cache/` の中だけを消せる |
| 解析ログ | `<状態フォルダ>/log` | `analysis-<日時>.log`。新しいものから 10 世代 |
| CSV の出力 | `<状態フォルダ>/output` | ［この呼び出し階層をCSVに出力…］の初期フォルダ。保存先はそのつど選べる |
| 進捗と作業ログをファイルにも残す | 残す | 外すとログファイルを作らない（コンソールには出る） |

このほかプラグインが作るものは 2 つある。どちらも移せない。

- `<状態フォルダ>/config/<プロジェクト名>/generated-config.properties` …
  自動で組み立てた設定。解析のたびに書き直す内部の作業ファイル
  （手で直したいときは、ビューの［解析に使う設定…］→［この内容を config/jche.properties に保存して編集する］）
- `<状態フォルダ>/jdk/` … 設定画面から取得した JDK

**Eclipse 自身のエラーログ**（プラグインの例外など）はこれとは別で、`<ワークスペース>/.metadata/.log`。
「ウィンドウ → ビューの表示 → エラー・ログ」で見える。

### 解析が遅い・返ってこないとき

1. ［解析ログ］の［開く］（またはビューの［▽］→［解析ログのフォルダを開く］）で
   最新の `analysis-*.log` を見る。解析の開始・進捗（10秒おき）・
   本体のログ・子プロセスの標準エラー・終了（所要時間つき）が時系列で入っている
2. 「Call Hierarchy Exporter」コンソールにも同じものが出る。解析の始めに作られるので、
   **あとからビューを開いても、それまでのログが見られる**
3. ヒープが足りないと、フェーズの区切りのログに「GC に取られた時間の割合」「GC 後の最大占有率」が出る。
   足りていなければ JVM 引数に `-Xmx4g` などを入れる（Eclipse 自身のメモリとは別枠）

## 5. つまずきやすいところ

| 症状 | 対処 |
|---|---|
| メニューに出てこない | Eclipse を `-clean` 付きで起動し直す。それでも出なければ「ウィンドウ → ビューの表示 → その他」で「影響調査 (Call Hierarchy Exporter)」を探す |
| 「解析に使う JDK が見つかりません」 | 設定画面で場所を指定するか、［JDK 25 を取得…］で取得する |
| 解析が失敗する | 「Call Hierarchy Exporter」コンソールに子プロセスの出力がそのまま出る（ログファイルにも残る）。設定ファイルの誤り（`project.root` など）が多い |
| 「解析サーバーが応答しません」 | 1 時間返らなかったときに出る。メッセージに最後の進捗と直近のログが付き、子プロセスは停止される（次の解析で起動し直す）。原因の切り分けは最新の `analysis-*.log` を見る |
| バナーに「解析できません」 | Java プロジェクトでなく、設定ファイルも無い状態。`config/jche.properties` を置くか、Java プロジェクトとして開く |
| 「ソースフォルダを特定できませんでした」 | ［解析に使う設定…］で `project.root` と `source.folders` を確かめる。Java プロジェクトなら、プロジェクトのプロパティ → Java のビルド・パス → ソース にソースフォルダが登録されているかを見る |
| ビューを開いても何も押せない | 一番上の［対象プロジェクト］でプロジェクトを選ぶ。一覧が空なら、Java プロジェクトとして開かれているかを確かめる |
| 木の続きが出ない／バナーに「1000 行で打ち切った」 | 画面は 1000 行までしか出さない。全部見るには右クリック →［この呼び出し階層をCSVに出力…］ |
| 解析結果が古い（⚠ が付く） | ツールバーの ⟳［再解析］。自動では解析し直さない |
| キャッシュを疑いたい・容量を空けたい | 設定画面の［解析キャッシュを削除］でファイルごと消す（次の解析は初回と同じだけかかる） |
| 新しい文法のソースが解析されない | 同梱の JDT の対応上限を超えている。対象バーの「設定: …」のツールチップに「解析できる Java」が出る |
| バナーに「⚠ n 件のファイルは構文エラーで読めていません」 | そのファイルの呼び出しは木にも CSV にも出ていない（「呼び出し元が無い」のではなく「読めていない」）。ファイル名は解析ログに出る。ソースの Java の版と `source.level` が食い違っていないか確かめる |
| 「設定ファイルを読めません … Malformed \uxxxx encoding」 | 設定ファイルに Windows のパスをそのまま書いている。properties ではバックスラッシュがエスケープなので、区切りを `/` にするか、バックスラッシュを2つ重ねる |

## 6. サーバーモード（プラグインが使っている経路）

プラグインは、解析本体を `--server` 付きで起動して標準入出力でやりとりしている。
同じことは手でもできる（CLI 利用者が自前の道具から使いたいときのため）。

```bash
printf 'HELLO\t1\nANALYZE\t/path/config/config.properties\nTREE\tcom.example.Foo#bar()\tcallers\tdepth=3\nSHUTDOWN\n' \
  | java -cp "lib/*:bin" jche.CallHierarchyExporter --server /tmp/jche-cache
```

要求と応答は TAB 区切りの1行で、`ANALYZE`（解析）・`FIND`（メソッドの確認）・
`AT`（ファイルと行から、その位置を囲むメソッドを引く）・`TREE`（木の切り出し）・
`EXPORT`（CSV 出力）・`CANCEL`（解析の中止）・`SHUTDOWN`（積んだ要求を処理し終えてから終わる）がある。
上の例のようにまとめて流し込んでよく、**末尾の `SHUTDOWN` が先に読まれても `ANALYZE` は完走する**。
実行中の解析を打ち切りたいときは `CANCEL` を送る。解析中は `#P` 行で進捗が、
`#L` 行でログが流れる。**フィルタ（深さ・文字列・テスト除外など）はサーバー側で効く**ので、
絞り込みのたびに解析し直すことはない。詳しい仕様は `src/jche/server/Protocol.java` のコメントにある。

## 7. テスト

プラグインまわりには6つの検査がある（いずれも GitHub Actions で実行）。

```bash
bash test/plugin/run.sh          # 版・ID・クラスの実在、解析本体がバンドルに混ざっていないこと
bash test/plugin-api/run.sh      # 古い Eclipse（4.6 相当）の jar と --release 8 でコンパイルできること
bash test/plugin-config/run.sh   # 自動生成した設定が、解析側と同じ読み方で読み戻せること
```
