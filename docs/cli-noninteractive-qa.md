# 引数ありのときは対話なしで実行する — 実装時の QA 一覧

[Issue #83](https://github.com/instreest/java-call-hierarchy-exporter/issues/83)
「CLI アプリが引数ありの場合に対話なしで実行する機能を追加したい」の対応で、迷ったこと・困ったことと、その結論を
Q&A の形で残す。

対応の要点:

- 起動コマンド（`java-call-hierarchy-exporter.sh` / `.cmd`）に設定ファイルを渡したときは、
  **一切尋ねずに解析だけを行って終わる**ようにした。尋ねる余地が残っていたのは起動コマンド側の
  「初回の設定」（JDK / JBang の置き場所）だけなので、そこを引数の有無で分けた
  - 引数あり … 尋ねない。`launcher.properties` が無ければ既定（このプロジェクトの中の `.jbang`）で作り、
    その旨を 1 行出す。標準入力・標準出力が端末でないとき（パイプ・CI）は作りもせず JBang の既定のまま（従来どおり）
  - 引数なし … 従来どおり、置き場所を選ぶ質問を出す
- `src/Jche.java` で、`-` で始まる知らない引数を設定ファイルのパスとして扱わず、使い方を出して終了コード 2 で終わるようにした
- README の Quick start を「起動コマンド + 設定ファイル」の 1 手順にした。対話モードの説明は後続のセクションへ移した
- `test/cli/run.sh` に「知らないオプション」と「引数ありのときは初回の質問をしない」の検査を足した

---

## 仕様

### Q1. 解析そのものは元から引数で動いたのに、何を足したのか

`src/Jche.java` は最初から「引数に設定ファイルがあれば `CallHierarchyExporter.runAll` を呼んで終わる」作りで、
メニューは出していなかった。残っていたのは Java が起動する前、起動コマンド（シェル / バッチ）側の初回の質問で、
`launcher.properties` がまだ無い環境では引数を付けても「置き場所を選んでください」で止まっていた。
バッチやタスクスケジューラから初めて呼んだときに止まるのが、この Issue の実害なので、そこを直した。
つまり足したのは「引数ありのときは起動コマンドも尋ねない」という一点と、周辺（知らないオプション・README・テスト）の整理。

### Q2. 引数ありで初回のとき、置き場所は何にするのか。尋ねないなら JBang の既定（`~/.jbang`）でよいのでは

既定（このプロジェクトの中の `.jbang`）にして `launcher.properties` に保存する。理由は 2 つ。

- 対話モードの質問の既定値（Enter だけで選ばれる `1)`）と同じにしたかった。これまでの Quick start も
  「このプロジェクトフォルダ内を選んでください」と書いていたので、引数ありでも同じ場所になるほうが、
  途中で対話モードに切り替えたときにダウンロードし直しにならない
- プロジェクトの中なら、フォルダごと消せば元に戻る。利用者に尋ねずに決める以上、後片付けしやすいほうを選ぶ

保存するのは、2 回目以降に「今どこを使っているか」が `launcher.properties` を見れば分かるようにするため
（対話モードの「環境設定」からも同じファイルを書き換える）。

### Q3. パイプや CI では `launcher.properties` を作らないのはなぜか

従来の動き（端末でなければ何も作らず JBang の既定で進む）をそのまま残した。
CI のワークフローは「チェックアウトした作業ツリーが汚れていないこと」を `git diff --exit-code` で検査していることがあり、
呼んだだけでファイルが増えるのは避けたい（`.gitignore` 済みではあるが、キャッシュの場所が黙って変わるのも困る）。
`.github/action/prepare.sh` が生成物を `RUNNER_TEMP` に置いているのと同じ考え方。
端末があるときだけ、人が見ている前で 1 行知らせて作る。

### Q4. 「引数あり」をどう判定するか

`--help` / `-h` 以外の引数が 1 つでもあれば「引数あり（対話なしの実行）」とみなす。
`--help` は表示するだけで解析しないので、置き場所を決める必要がない（従来から質問の対象外）。
`.cmd` 側は cmd の `if` で見るので第 1 引数 `%~1` だけを見ている。第 2 引数以降だけに設定ファイルが来る形
（`--help` と併記する等）は実際には無いため、単純さを採った。

### Q5. 知らないオプションを弾くのはやりすぎではないか

`java-call-hierarchy-exporter.sh --offline` のように jbang のオプションを渡したくなる人がいるが、
これまではそれが設定ファイルのパスとして扱われ「設定 --offline の処理に失敗しました」という分かりにくい失敗になっていた。
対話なしで動かす以上、引数の誤りは早く・はっきり返すほうがよいので、`-` で始まる引数は使い方を出して終了コード 2 で終わる。
jbang のオプションは `launcher.properties` の `JCHE_JBANG_OPTS` で渡す（使い方の最後に書いてある）。
`-`（単体）だけは弾かない。ファイル名として `-` を渡す用途は無いが、パスの一部と紛れる書き方を無理に禁止しないため。

### Q6. 終了コードをどう決めたか

- 0 … すべての設定ファイルが成功
- 1 … 1 つでも失敗（`CallHierarchyExporter.runAll` が返す失敗件数が 1 以上。従来どおり）
- 2 … 引数が誤っている（知らないオプション）

「実行したが結果が失敗」と「そもそも呼び方が間違い」を分けると、バッチ側で再実行の判断ができる。
2 は Unix の慣習（`getopt` の使い方エラー）に合わせた。

## ドキュメント

### Q7. Quick start を引数ありの手順にすると、対話モードの存在が見えなくならないか

Quick start の直後に 1 段落だけ「引数なしで起動すると対話モードになる」ことと、初回の置き場所の扱いを書き、
詳細は「起動コマンド」のセクションへリンクした。README の Quick start は「動かして CSV を見るまでの最小手順」だけに
する決まり（[AGENTS.md](../AGENTS.md)）なので、分岐や選択肢を Quick start 側に持ち込まない。

### Q8. 「起動コマンド（対話モード）」という見出しはどうしたか

対話モードは起動コマンドの一つの姿でしかなくなったので、見出しを「起動コマンド」にして、
引数と動きの対応表（設定ファイル / なし / `--help`）を先頭に置いた。README 内からこの見出しへのリンクは
Quick start の 1 か所だけなので、`#起動コマンド` に直して整合を取った。

## テスト

### Q9. 「尋ねない」ことをどう検査するか

`test/cli/run.sh` は端末を持たない（パイプで答えを流し込む）ので、そのままでは
「端末がある初回」を再現できない。検査したいのは「引数を付けたら質問にもメニューにも入らないこと」なので、
`launcher.properties` を消したうえで引数ありで起動し、ログに「初回の設定」と「1) 解析を実行する」が
出ていないことを見る形にした。端末がある場合の分岐（既定で作って 1 行知らせる）は、
`script -qec`（擬似端末）で手元で確認した。常時の検査に入れなかったのは、`script` が環境によって
オプションの綴りが違い（util-linux と BSD）、CI の OS 差で落ちやすいため。

### Q10. `.cmd` の変更をどう確かめるか

`.cmd` は cmd.exe でしか動かせないので、`test/cli/run.sh` の最後にある「中身を読むだけ」の検査
（ラベルの二重定義が無い / `goto`・`call` の飛び先がある / CRLF / MS932）に頼る。
今回 `:first_run_default` というラベルを増やしたので、この検査が飛び先の抜けを拾う。
実際、編集の途中でラベル名の置換が `call :first_run_prompt` の行にも当たり、ラベルの中身が空になった状態を
この検査で気づけた（`docs/cli-app-qa.md` の Q15 のとおり、`.cmd` は MS932 のまま編集する必要があるので、
置換はエンコーディングを指定したスクリプトで行っている）。
