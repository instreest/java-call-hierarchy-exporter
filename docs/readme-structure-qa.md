# README の構成 — Q&A

README を、初めて見る Java 開発者が上から順に読めば使い始められる並びに組み直した。
前半を初めて使う人の道、区切り線の下を「出力のリファレンス」にし、README の範囲を外れる説明は docs/ に移した。

  具象クラスの解決（ラベルの表）、ラムダ式・メソッド参照（要約）
- docs/ へ移したもの:

  | 何を | 移した先 |

## Q&A

### Q1. README を README.md（英語）と README.ja.md（日本語）に分けなかったのはなぜか

日本語が正本という関係が逆になり、docs/ から日本語の見出しのアンカーへ張ったリンクをすべて張り直すことになるため。
1 ファイルのまま、点検の仕組みで食い違いを防ぐほうを採った。

### Q2. 出力のリファレンスを docs/ に移さず README に残したのはなぜか

docs/ は日本語だけなので、移すと英語の読者が CSV の列と記号を読めなくなる。AGENTS.md も README の範囲に
「出力 CSV の読み方」を含めている。移したのは、README の範囲を外れる仕組みや運用の説明（解決の段、ラムダの細部、
jar の被参照の指定、キャッシュ）だけにした。英語の読者はこれらを失うが、出力を読むのに要る要約とラベルの表は残した。

### Q3. 見出しを変えずに ## から ### に下げたのはなぜか

`#出力ファイル`・`#具象クラスの解決`・`#ラムダ式メソッド参照` などへ docs/ からリンクが張られている。
GitHub のスラッグは見出しの深さに依らないので、文字を変えなければリンクは切れない。
段の番号を指していた docs のリンク（library-call-rules.md・call-rules-unification-design.md・instance-analysis-plugin.md）は、
段の表の移った static-analysis-limits.md の 9 節へ張り直した。

### Q4. 概要を短いままにしたのはなぜか

所有者が 50b5292 で、概要から CSV の例・特長の箇条を外し、2 文と開発中の注意・案内の表にした。
その判断を尊重し、CSV の例は「1 行の読み方」の中にだけ置いた。概要には案内の表の 1 行（出力のリファレンス）だけを足した。

### Q5. 点検は何を見て、何を見ないか

見るもの: 節の印の並び、節ごとの表の行・コードブロック・箇条の数とリンク先のファイルの集合、README の中の
アンカー、docs/ から README へのアンカー、README の JDT の版と `//DEPS`。
見ないもの: 文の中身（訳の正しさ）、起動コマンドの文言や config のコメントの中の「README の『…』」という書き方
（リンクではないので機械で結べない。節名を変えたら `grep -rn README` で探す）。

### Q6. 用語と表記の決まりは何か

| 使う語 | やめる語 |
|---|---|
| 設定ファイル | コンフィグ、文中の config |
| 依存 jar | 依存jar |
| 起動コマンド | 起動スクリプト |

和文と英数字・インラインのコードの間には半角の空白を入れる（見出し・リンク先・コードの中は変えない）。
設計の理由（「〜なので揃えています」）は README に書かず、利用者の行動を変える理由だけを残す。

### Q7. 動作条件と制約を Quick start の後ろに置いたのはなぜか

所有者の判断（b781571）。初めての人がまず動かして結果を見られるよう、Quick start と結果の読み方を先にした。
依存 jar が手元に無いまま動かしても解析は最後まで進み、`warnings.txt` が不足を知らせるので、
先に動作条件を読まなくても手順 4 で気づける。
