「JBang Wrapper のインストールフォルダ jbangw に JBang の MIT ライセンス表記と README を追加したい」

対応の要点:

- ルート `README.md` … 上記への導線を 2 箇所（Quick start と jbangw テストの節）に追加

## ライセンスまわり

### Q1. ルートに Apache-2.0 の LICENSE があるのに、フォルダ内に別の LICENSE を置いてよいか

置いてよいし、置くべき。MIT は「上記の著作権表示とこの許諾表示を、ソフトウェアの複製または
重要な部分すべてに含めること」を条件にしている。`jbangw/` の 3 スクリプトは JBang の複製その
ものなので、複製と同じ場所に表示が要る。ルートの Apache-2.0 は本体（`src/` など）のものなので、
これで置き換えることはできない。

サブフォルダに `LICENSE` を置いても GitHub のリポジトリ全体のライセンス表示（ルートの
Apache-2.0）は変わらない。誤解を避けるため、`jbangw/README.md` に「このフォルダの 3 スクリプト
だけは Apache-2.0 ではなく MIT」と明記した。

### Q2. LICENSE の中身は書き写すのか、取得するのか

取得する。MIT の条件は「上記の著作権表示」をそのまま含めることなので、著作権者名や年を
書き間違えると条件を満たさない。本家の
`https://raw.githubusercontent.com/jbangdev/jbang/main/LICENSE` をそのまま取得して置いた
（Copyright (c) 2020 Max Rydahl Andersen）。

### Q3. ファイル名は `LICENSE` か `LICENSE.jbang` か `NOTICE` か

`LICENSE` にした。理由は次のとおり。

- `NOTICE` は Apache-2.0 の仕組みで、MIT には出てこない。混ぜると読み手が迷う
- `LICENSE.jbang` のような名前は、そのフォルダに複数の出所が混ざっているときには意味があるが、
  `jbangw/` の中身は JBang だけなので分ける理由がない
- 「そのフォルダの LICENSE はそのフォルダに適用される」という一番素直な読み方で正しくなる

## README の中身

### Q4. 「当リポジトリでの修正点」はどこから書き起こすか

`test/jbangw/run.sh` の検査項目とそのコメントから書き起こした。修正の一覧としては、
コミットログ（`84f3e7d`, `f094544`, `a71be2c`, `caac189`, `c18a919`）よりこちらのほうが確実。
コミットは「あとで書き直した修正」も含むため時系列を追わないと現在の姿が分からないのに対し、
`run.sh` は「いま守るべき状態」だけを列挙しているため。

副作用として、README と `run.sh` は同じものを別の形で書いていることになる。ずれると困るので、
README の更新手順に「`run.sh` の該当項目とこのファイルの両方を直す」と書いた。

### Q5. スクリプトを「そのまま持ち込んだ」のか「修正して取り込んだ」のか、どちらと書くか

両方書いた。出所としては本家の `src/main/scripts/` の 3 ファイルをそのままコピーしたもので、
そのうえで JDK 自動取得まわりの不具合を当てている、という 2 段構えが実態に一番近い。
「取得元」と「当リポジトリでの修正点」を別の節に分けたのはこのため。

### Q6. 実行方法の説明をルート README と二重に書くことにならないか

`jbangw/README.md` の冒頭に最小限のコマンド例だけ置き、設定ファイルの書き換えや出力形式は
ルート README に任せた。`jbangw/` の中身だけを見た人（たとえば同梱スクリプトの出所を確かめに
来た人）が、何のためのフォルダか分からないまま終わるのを避けたかったため。

## 実装中に見つかったこと

### Q7. 同梱スクリプトは本当に「修正済み」の状態か

違った。作業前に本家の 3 ファイルを取得して `jbangw/` と比べたところ、**バイト単位で同一**
だった。つまり修正はいま入っていない。コミット `314c140`（jbang wrapper fetch from upstream）が
本家の内容で上書きし、PR #46 で入れた修正が巻き戻っていた。

`bash test/jbangw/run.sh` を実行すると、まさにこの巻き戻りを検出して FAIL する。
検査はねらいどおり働いていて、結果を見ていなかっただけ。

### Q8. その場で修正を当て直すか

当て直さなかった。Issue #50 の範囲はライセンス表記と README の追加で、ラッパースクリプト本体の
変更は別の話だから。ただし、実在しない修正を README に書くと嘘になるので、
「当リポジトリでの修正点」の冒頭に現状の注意書き（`314c140` で巻き戻っており `run.sh` は
現在 FAIL する）を置き、当て直しは別対応とした。

当て直し自体は `git checkout f1720cd -- jbangw/jbang jbangw/jbang.cmd jbangw/jbang.ps1` で足りる
（`f1720cd` は PR #46 のマージコミット）。

### Q9. LICENSE と README を足すことで既存のテストが壊れないか

壊れない。`test/jbangw/run.sh` は `jbang` / `jbang.cmd` / `jbang.ps1` の 3 ファイルを名指しで
読むだけで、フォルダ内を走査していないため、ファイルが増えても影響しない。
